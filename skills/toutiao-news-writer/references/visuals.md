## 1. 封面在信息流里的角色

- 单图：标题与封面并排，是一个视觉单元。
- 三图：三张缩略图并排，信息量大但容易糊；三张必须同风格、同色调、同比例。
- 无图：纯文字卡片，靠来源权威和标题硬度，适合快讯。

分工：

| 元素 | 回答的问题 |
|---|---|
| 封面 | 关于谁、发生在哪、画面是什么 |
| 标题 | 发生了什么、为什么和我有关 |

**不要复述**。封面已经是人脸，标题就不用再重复三遍名字；封面已经是大字报，标题就不要再写同样的口号。

## 2. 五种版式

模板文件：`assets/cover-lab.html`，画布 1280×720。用 `body[data-style]` 切换。

| style | 适合 | 视觉特征 | 关键参数 |
|---|---|---|---|
| `photo` | 突发、现场、人物 | 全屏照片 + 底部渐变 + 压字 | `__IMAGE__` `__KICKER__` `__TITLE__` `__SOURCE__` |
| `bignum` | 数据、金额、年龄、比例 | 深色底 + 巨大数字 + 一句判断 | `__NUMBER__` `__UNIT__` `__TITLE__` |
| `split` | 对比、前后、A vs B | 左右分屏 + 中缝 + 两个标签 | `__IMAGE_A__` `__IMAGE_B__` `__LABEL_A__` `__LABEL_B__` `__TITLE__` |
| `bulletin` | 政策、通报、权威发布 | 浅色纸感 + 红色标签 + 大字 | `__KICKER__` `__TITLE__` `__SUB__` `__SOURCE__` |
| `stats` | 财报、榜单、三个关键数 | 深绿渐变 + 三栏数据 | `__STAT1..3__` `__LABEL1..3__` `__TITLE__` |

### 选型规则

- **有人、有现场** → `photo`。人脸/主体占画面 1/3 以上。
- **一个数字最有冲击力** → `bignum`。数字不超过 5 位，单位单独一行。
- **两组信息在打架** → `split`。左右必须真的可比（前/后、A/B、国内/国外）。
- **官方口径、政策、通报** → `bulletin`。字要少，最多 2 行标题。
- **三个指标撑起全文** → `stats`。三个数必须同层级，不要混入无关指标。

## 3. 封面制作流程

```bash
# 1) 复制模板
cp assets/cover-lab.html work/cover.html

# 2) 编辑 work/cover.html：
#    - body data-style="photo|bignum|split|bulletin|stats"
#    - 替换 __TITLE__ / __KICKER__ / __SOURCE__ / __NUMBER__ 等文字占位符
#    - 替换 __IMAGE__ / __IMAGE_A__ / __IMAGE_B__ 为图片路径
#      路径相对于 work/cover.html，例如 ../assets/fig-01.jpg

# 3) 截图（2x 更清晰）
node scripts/shot.mjs work/cover.html assets/cover.png --size 1280x720 --scale 2
```

文字也可以用 URL 参数快速试排（中文和 `%` 需编码；图片仍需替换占位符）：

```bash
node scripts/shot.mjs "work/cover.html?style=bignum&number=423万&unit=人&title=只招3.5万" assets/cover.png
```

**图片留空也不会破图**：未替换的 `__IMAGE__` 会被自动隐藏，只显示底色/渐变。所以先排版、后补图是安全的。

**版式硬规则**
- 标题最多 3 行，超过就删字，不要缩字号。
- 主体（人脸、logo、核心物体）放在中间 **60% 安全区**，四周至少留 8% 边距。
- 封面不要放二维码、联系方式、其他平台水印。
- 同账号封面保持统一色卡（主色 ≤2 个），形成识别度。

## 4. 文中配图规划

先写规划表，再找图。不要边写边随手配图。

| 位置 | 内容 | 类型 | 来源 | 图注 |
|---|---|---|---|---|
| 开头后 | 事件现场 | 现场图 | 官方通稿 | 11月9日，XX 现场 |
| 01 节后 | 关键人物 | 人物图 | 机构发布 | XX 在发布会上 |
| 02 节中 | 数据对比 | 图表 | 自制 | 数据来源：XX，2026Q3 |
| 结尾前 | 时间线 | 信息图 | 自制 | 事件时间线 |

数量：

| 文章类型 | 配图数 |
|---|---|
| 快讯 | 0–1 |
| 汇编 | 3–6（每块 1 张） |
| 解读 | 4–8 |
| 故事化 | 3–6 |

- 每 300–500 字一张，长文不超过 1000 字无图。
- 首图承担封面职能；首图选错，后面救不回来。
- 横图优先；连续两张竖图会打断阅读。

## 5. 图源优先级与版权

按顺序找，找到就停：

1. **用户提供的图片**（确认用户有权使用）。
2. **官方来源**：政府/企业公告、机构新闻稿、当事方社媒发布。
3. **明确授权**：可商用图库、Wikimedia Commons、CC 协议图片（保留授权链接）。
4. **AI 生图**：用于概念示意、场景还原，必须标注“示意图”。
5. **自制信息图**：数据、时间线、对比，最安全。

**不要用**：搜索引擎直接下载、带水印图、其他账号的配图、明星偷拍、聊天记录里未打码的头像/手机号。

下载并记录来源：

```bash
node scripts/download-image.mjs "<url>" "assets/fig-01.jpg" \
  --source "XX 政府官网 | https://... | 官方公开信息"
```

脚本会追加到 `assets/sources.md`。交付前检查：**每张图都有一行来源**。

## 6. AI 生图的边界

只有在检测到 `mmx` 可用时才用：

```bash
mmx image generate --prompt "<画面描述>" --output assets/fig-02.png
```

- 可以用来做：概念图、场景示意、情绪图、封面背景。
- **不可以**用来伪造新闻现场、当事人肖像、事故画面、文件截图。
- 画面里不要生成文字（容易乱码）；文字交给 HTML 模板排版。
- 必须在图注和 `sources.md` 标注「AI 生成示意图」。

没有 API key 时，用 `cover-lab.html` 的信息图/大字报替代，不要硬等。

---

## 7. 图注写法

图注不是“图片来源：网络”，而是**补充信息**：

- ✅「11月9日，施工人员在厦门段主桥合龙现场作业。来源：XX 发布」
- ✅「2020–2026 年考研报名人数变化。数据来源：教育部」
- ✅「AI 生成示意图：算法推荐如何影响用户决策」
- ❌「图片来源于网络」
- ❌「现场图」

## 8. 交付前视觉检查

- [ ] 缩到 300px 宽，3 秒能看出主体
- [ ] 标题没被裁，主体没被切，文字没贴边
- [ ] 封面与标题互补，不复述
- [ ] 三图模式三张比例/色调一致
- [ ] 无其他平台水印、二维码、联系方式
- [ ] 每张图有来源，AI 图有标注
- [ ] 图注有信息增量，不是“图片来源网络”
